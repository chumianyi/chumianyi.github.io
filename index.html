开发文档

从解压到上线，从接入平台到写第一个插件。本文对应 YueWuBot v1.4.1，所有配置都在本地完成，不需要任何在线服务。

安装

一条命令建环境、装依赖、起服务。

 接入平台

OneBot v11 / v12、QQ 与微信官方。

 写插件

一个 main.py 加一个 m.json。

快速开始

YueWuBot 是单文件 Python 核心的聊天机器人，专门为 QQ 官方机器人制作：在 QQ 开放平台创建应用，填上 AppID 与 AppSecret 即可对话，不需要任何第三方协议端。同一个内核也兼容 OneBot v11 / v12 与微信官方接口。准备一台装了 Python 3.6 或更高版本 的机器就能跑，内存常驻约 40 MB。

纯净版仅 YueWuBot 本体与 zip 插件，插件市场读取官方 p.json。
AstrBot 完整兼容版额外带兼容层，可装 AstrBot 生态插件（Beta）。
三步跑起来
# 1. 解压并进入目录
unzip YueWuBot-1.4.1-src-Repo.zip
cd YueWuBot-1.4.1-Repo

# 2. 一键安装并启动（首次会显示免责声明，输入 Y 同意）
chmod +x start.sh && ./start.sh

# 3. 安装第 1 步设置管理员账号与密码（密码输入不回显）
#    账号 ≥5 位；密码 ≥10 位，含大小写、数字与特殊字符
# 4. 浏览器打开 127.0.0.1:6199，用刚才的账号登录
./start.sh account    忘记账号名时可以再查一次
./start.sh setpass Chumian   想换账号名或重设密码
先接平台再聊天。控制台能看到机器人在线，但只有配置了平台连接之后，消息才会进来。四类平台的配置方式见 平台接入。

平台接入

v1.4.1 原生支持四类平台：OneBot v11、OneBot v12、QQ 官方机器人与微信官方机器人。OneBot 最多 20 条连接同时在线，每条链路独立管理；四类链路可以并存，回复只会回到消息来源的那一条。

OneBot v11任何兼容 v11 的实现，走标准 WebSocket 与 11 号 API，双向连接。
OneBot v12v12 事件与 API：get_self_info、send_message 与 detail_type。
QQ 官方机器人AppID + AppSecret 换 AccessToken，接入官方网关，处理 C2C 与群 @ 事件。
微信官方机器人公众号回调验签 + 客服消息回复，每个账号一个回调地址。

OneBot：两种连接方向

server · 平台连入YueWuBot 监听 WebSocket，由平台侧主动连过来。适合平台与机器人同机或可直连的场景。
client · 机器人主动连YueWuBot 主动连接平台提供的 WS 地址。适合平台在容器或内网、机器人无法被反向访问的场景。
WebSocket 地址
# 默认连接（v11 / v12 共用同一个入口）
ws://127.0.0.1:6199/ws

# 指定连接 ID 与访问令牌（推荐用于多平台）
ws://127.0.0.1:6199/ws?conn=snow&access_token=YOUR_TOKEN

# 机器人主动连出时，填写平台侧地址
ws://127.0.0.1:3001

OneBot 连接配置项

字段说明
kindonebot11 或 onebot12
id连接唯一标识，用于 ?conn= 路由，如 snow、nap
name控制台显示名称
directionserver 等待连入 / client 主动连出
urlclient 模式下要连接的目标地址
access_token该链路的鉴权令牌，可留空表示不鉴权
enabled是否启用这条连接

QQ 官方机器人

在 QQ 开放平台创建机器人后，把 AppID 与 AppSecret 填进「平台 → 新增连接 → QQ 官方机器人」。连接时依次调用 getAppAccessToken 换取令牌、拉取 /gateway 地址，随后按心跳 op1、鉴权 op2、重连 op7、失效 op9 维护长连接。收到 C2C_MESSAGE_CREATE 与 GROUP_AT_MESSAGE_CREATE 事件后走同一套模型与插件。

官方机器人需要先在开放平台申请到「私聊」与「群 @」权限，并在后台配置好 IP 白名单；intents 默认只订阅群与私聊消息事件。

微信官方机器人

「平台 → 新增连接 → 微信官方机器人」填入公众号的 AppID、AppSecret 与自定义 Token。每条连接有独立回调地址：

公众号后台填写
https://你的域名/wechat/<连接 ID>

# 例：连接 ID 为 wx 时
https://bot.example.com/wechat/wx

回调走 SHA1 验签，校验通过返回 echostr；消息事件解析后按客服消息接口 cgi-bin/message/custom/send 回复，48 小时内可多次回复。微信要求公网可达的 https 地址，请用反向代理把 /wechat/ 转发到控制台端口。

每条消息都会带上它的来源连接，回复、点赞与原生 API 调用会自动回到原链路，不会串到其他平台。旧版单连接设置（platform.mode / platform.url / platform.access_token）会自动迁移为名为 默认连接 的一条链路。

容器部署：平台运行在 Docker 中时，地址请指向宿主机网关而非 127.0.0.1，并在容器侧配置 host-gateway。纯净源码包不包含平台容器。

控制台

安装第 1 步就会设置管理员账号：账号 5–32 位（字母、数字、_ . -），密码至少 10 位且需同时包含大写字母、小写字母、数字与特殊字符，可选 emoji；输入密码时不显示任何字符，光标不动属正常现象。密码以 PBKDF2-SHA256（20 万次迭代）加盐摘要保存在 data/config.json，任何页面都不会回显明文。安装时跳过或忘记账号名，可用 ./start.sh setpass 重新设置，./start.sh account 查看当前账号。登录态是 24 小时有效的会话，同一 IP 每分钟最多 8 次登录尝试。

试聊不经过 QQ，直接与当前模型对话以验证配置
模型接口地址、Key、模型名、人设与超时重试参数
平台四类平台连接的增删改、连接状态与最近错误
插件上传 zip、启停、参数配置、依赖安装与休眠状态
插件市场读取官方 p.json，点安装即克隆并生效
日志实时运行日志流
设置修改密码、更新检查、运行参数、重启与退出登录

模型配置

支持 OpenAI Chat Completions 与 Anthropic Messages 两种协议，在控制台「模型」页选择协议后填写地址、Key 与模型名即可。

参数默认值说明

temperature0.85采样温度

Anthropic 协议使用 x-api-key 与 anthropic-version: 2023-06-01 鉴权，人设作为顶层 system 字段发送，回复从 content 文本块提取。地址填 https://api.anthropic.com 即可。客户端错误（4xx）不会重试，会直接给出明确提示；服务端错误与网络异常按短超时快速重试。

消息规则

发送方式行为
普通消息群聊中需要 @ 机器人才会触发对话
/内容以斜杠开头，群聊中无需 @ 直接进入对话
#内容以井号开头，开启快速群对话
#YueWu返回固定版式状态：机器人信息、运行时间、运行状态、操作系统、当前负载、当前版本、更新检测
插件触发词声明了 triggers 的插件可免 @ 全局识别并自动唤醒

插件休眠与唤醒由核心自动管理：只有声明了触发词的插件会被闲置回收，消息到达时按需加载，因此长期运行也不会持续占用内存。

图片收发

v1.4.1 起消息与图片双向打通：用户发来的图片会转成 data URL 随消息一起交给模型；模型回复里的图片链接会被自动拆出来，作为图片消息发出。

方向行为
接收解析消息段中的 image，下载后转 data URL（单张上限 8 MB），作为多模态输入发给模型
发送识别 Markdown ![](url) 与 <img src>，先发文字、再逐张发图，正文中不再残留链接
开关「模型」页的接收图片与自动发图两个开关，分别控制两个方向
插件ctx.images 拿到本条消息的图片地址，ctx.send_image(src) 直接发图
只有支持视觉的模型才能理解图片。使用纯文本模型时建议关闭「接收图片」，避免把大段 data URL 塞进上下文。

更新与升级

控制台会读取官方 v.json 判断版本，发现新版本时在顶栏提示，点一下即可完成下载、校验、备份、覆盖与重启。

字段说明
version最新版本号，与当前 VERSION 做数值比较（1.10.0 大于 1.9.9）
package更新包直链，必须是 https://；包内任意层级含 yuewubot.py 即可
sha256更新包摘要，校验不一致立即中止，不会覆盖任何文件
notes更新说明，字符串数组，控制台逐条展示
v.json 示例
{
  "version": "1.4.1",
  "date": "2026-11-09",
  "notes": ["控制台重写为侧边栏", "新增四类平台接入"],
  "package": "https://你的域名/downloads/YueWuBot-1.4.1-src-Repo.zip",
  "sha256": "27a1bc61…3fd7e67"
}

覆盖时保留 data/、plugins/、.venv/、__pycache__/ 与 .git/，其余文件先备份到 data/backups/<旧版本>-<时间>/ 再替换。完成后进程以退出码 3 退出，由 systemd 或 start.sh 守护拉起，因此请务必用服务方式运行，前台手动运行时更新后不会自动回来。检测地址可在「设置 → 版本更新」里改，方便自建更新源。

插件依赖

插件可以自带依赖。加载前核心会读取插件目录下的 requirements.txt，或 m.json 里的 requirements 数组，把它们装进项目虚拟环境。

两种声明方式
# 方式一：requirements.txt（每行一个包）
pillow>=9.0
qrcode

# 方式二：m.json 中声明
{ "requirements": ["pillow>=9.0", "qrcode"] }

安装走控制台的 pip 镜像链（中科大 → 清华 → 官方），结果写入 data/plugin_deps.json。为安全起见，只接受包名与版本约束这一行写法：以 - 开头的选项、含 ://、路径分隔符或 @ 的行会被拒绝并回显在「非法行」里，避免通过依赖注入执行任意命令。插件卡片上的「重装依赖」可以强制再装一次。

m.json 示例

  "version": "1.0.0",
  "author": "You",

  "commands": [
    { "name": "hello", "handler": "cmd_hello", "description": "打个招呼" }
  ],
  "config": {
    "times": { "type": "number", "label": "次数", "default": 1 }
  }
}

main.py 约定

核心按名称查找钩子函数，支持同步与异步两种写法。指令函数接收 (ctx, args)，钩子函数按钩子签名接收 ctx 或 bot。分发前会注入插件配置到 ctx.cfg，用 ctx.reply() 回复，用 ctx.api() 调原生 OneBot 接口。

main.py 示例
async def cmd_hello(ctx, args):
    times = int((ctx.cfg or {}).get("times") or 1)
    await ctx.reply("你好呀～" * times)

async def on_message(ctx):
    if "你好" in ctx.text:
        await ctx.reply("在的")
        return True          # 返回 True 表示已处理，不再往下分发
    return False

async def on_startup(bot):
    print("[hello] 已加载")

需要持久化的数据写入插件目录下的 data/（或 assets/），插件目录会随部署一起保留，重启不会丢失。

注意：插件代码以与主进程相同的权限执行，请只安装你信任来源的 zip 包。生产环境建议使用独立低权限账号运行机器人。

插件 API

ctx 是每条消息的上下文对象，插件里最常用的能力都挂在它上面。

属性 / 方法说明
ctx.text本条消息的纯文本（图片、表情会被转成占位符）
ctx.user_id / ctx.group_id发送者 QQ 与群号；私聊时 group_id 为空
ctx.sender发送者昵称
ctx.message_typegroup 或 private
ctx.images本条消息里的图片 URL 列表
ctx.raw原始 OneBot 事件，需要读消息段时用它
ctx.cfg当前插件的配置字典（来自 m.json 的 config 定义）
await ctx.reply(text, at=False)回复到当前会话；at=True 时在群聊里先 @ 发送者
await ctx.send_image(src)发送图片，支持 URL 或本地路径
await ctx.api(action, **params)调用任意 OneBot v11 接口，如 get_group_list
ctx.bot.segments(event)把事件解析成消息段数组，兼容数组与 CQ 码
ctx.bot.plugins.is_admin(uid)判断是否在控制台管理员名单里
ctx.ob.send_rich(...)发送由多个消息段组成的富消息
调用原生接口
async def cmd_groups(ctx, args):
    resp = await ctx.api("get_group_list")
    groups = resp.get("data") or []
    await ctx.reply("机器人加入了 %d 个群" % len(groups))

发布插件

把插件目录放进 yuewubot-plugins 仓库，再往 p.json 的 plugins 数组里加一条索引，控制台的插件市场就能搜到并安装。

检查项要求
目录仓库根目录下独立子目录，与 p.json 的 dir 一致
文件main.py、m.json、icon.png（512×512 更清晰）
图标链接https://raw.githubusercontent.com/<owner>/<repo>/main/<dir>/icon.png
版本改了功能就升 m.json 的 version，索引同步
敏感信息不要把 Cookie、Token、密钥写进代码或配置默认值
管理员相关插件不要写死管理员 QQ：发布后所有安装者都会共用那个号码。应当读取 cfg["admins"] 或留空的配置项。

常见问题

控制台打不开确认服务在运行（./start.sh status）、端口未被占用，且访问的是 127.0.0.1:6199。
平台一直离线核对连接方向、WS 地址与令牌；容器环境检查宿主机网关；查看日志中的最近错误。
模型回复失败用「测试连接」验证 Key 与模型名，检查 timeout 与 retries；4xx 通常是配置问题。
忘记控制台密码服务器上执行 ./forgot-password.sh，会重置为 20 位随机密码；明文 100 秒后自动从日志与文件中清除。
更新后没自动回来一键更新依赖进程以退出码 3 退出后被守护拉起。若在前台手动运行，需要自己重新执行 ./start.sh。
插件装不上依赖看 data/plugin_deps.json 的 invalid / error 字段；含 - 开头、URL 或路径的依赖行会被安全策略拒绝。
插件不生效确认 zip 根目录含 main.py 与 m.json、插件已启用；免 @ 触发需在 triggers 中声明。
B站直链 403CDN 防盗链要求 Referer。用播放器链接在浏览器打开，直链交给下载器并附带页面地址。
内存越来越高检查是否插件未声明触发词；没有触发词的插件不会被闲置回收，长期驻留属于正常。

日志可通过 ./start.sh logs 或控制台「日志」页查看。若使用 systemd，也可执行 journalctl -u yuewubot -n 100 --no-pager。
