开发文档

从解压到上线，从接入 QQ 机器人到写第一个插件。本文对应 YueWuBot v1.4.2，所有配置均在本地完成。

本页内容

安装与运行 两个版本 目录结构 平台接入 控制台 模型配置 消息规则 插件开发 排障与维护 许可证

安装与运行

准备一台装有 Python 3.6 或更高版本 的机器即可。首次执行会先显示免责声明，输入 Y 或 yes（不区分大小写）同意后自动完成一键安装：创建独立虚拟环境、安装 aiohttp、生成 30 位访问令牌并启动服务。同意状态会记录，后续执行不再重复询问。

终端
unzip YueWuBot-1.4.2-QQ.zip
cd YueWuBot-1.4.2-QQ
./start.sh          同意免责声明后一键安装并启动
./start.sh token    查看 30 位访问令牌

部署完成后，日常启动只用这一条
./已部署后启动.sh

脚本会先探测可用的 Python 解释器，在项目内创建 .venv。检测到 systemd 时注册为 yuewubot.service 并设置开机自启，否则以后台进程方式运行，PID 写入 .pid。

start.sh 负责安装与修复环境，已部署后启动.sh 只负责把已部署的服务拉起来：不重跑免责声明、不装依赖、不改配置，支持 start / restart / stop / status / logs。

访问令牌

控制台不再使用账号密码，只有一串 30 位字母与数字混合的访问令牌。首次启动自动生成，打印在终端并写入 data/TOKEN.txt（权限 600）。登录时直接粘贴，会话有效期 24 小时。

命令作用
./start.sh token查看当前令牌
./start.sh token --reset重新生成，旧令牌与会话立即失效
./reset-token.sh同上，独立小脚本
./reset-token.sh 自定义令牌指定一个 30 位字母数字令牌

依赖源与架构

安装依赖时依次尝试 本站托管包 → 中科大源 → 清华源，任一成功即继续。本站托管包提供 x86_64 / X64 / x86-x64 / AMD64、ARM64 / aarch64、X86 / i686 的 Python 3.6 预编译 wheel，另附平台无关源码包与纯 Python wheel 覆盖其他架构和更高的 Python 版本。托管包索引见 /pip/。

管理命令

命令作用
./start.sh安装依赖并启动（默认动作）
./已部署后启动.sh已部署后直接启动，不重跑安装
./已部署后启动.sh restart / stop / status / logs日常管理
./start.sh fg前台运行，便于调试，Ctrl+C 退出
./start.sh stop / restart停止 / 重启服务
./start.sh status查看运行状态与端口监听
./start.sh logs查看实时日志
./start.sh deps / doctor仅修复依赖 / 环境诊断
./start.sh uninstall移除服务，保留配置与插件数据

环境变量

变量默认值说明
YW_PORT6199控制台监听端口
YW_HOST127.0.0.1监听地址；对外暴露可设为 0.0.0.0
YW_ACCEPT无非交互环境下设置 Y / y / yes（任意大小写）视为已同意免责声明
YW_SKIP_TOKEN无安装时跳过令牌生成，稍后用 ./start.sh token --reset
YW_PIP_PAGES本站 /pip/自定义首选托管包地址
PIP_MIRROR清华源第三级备用 pip 镜像地址，可换成内网源
安全提示：控制台默认只监听回环地址。若需公网访问，请通过 Nginx 等反向代理转发并启用 HTTPS，不要直接把 0.0.0.0 暴露在公网。

两个版本

两个版本共用同一个核心与控制台，区别只在接入协议。开源版只做 QQ 官方机器人，完整版在其上叠加 OneBot 与微信。

能力开源版（MIT）完整版（私有）
QQ 官方机器人支持，AppID + AppSecret支持
OneBot v11 / v12不支持支持，最多 20 条连接
微信官方机器人不支持支持，回调 + 客服消息
内置插件9 个13 个（含点赞、审批、广播）
访问令牌登录 / 新手引导支持支持
源码公开可改不公开
插件差异：依赖 OneBot 动作接口的插件（点赞、入群与好友审批、群广播、群欢迎）只在完整版提供。开源版里 ctx.api() 会抛出说明性异常，插件应改用 ctx.reply() 与 ctx.send_image()。

目录结构

部署包保持极简，运行时产生的目录不会随包分发。

项目目录
YueWuBot-1.4.2-QQ/
├── yuewubot.py       主程序（单文件核心）
├── start.sh          安装与管理脚本
├── 已部署后启动.sh   部署后的日常启动
├── reset-token.sh    重置访问令牌
├── web/              控制台前端与内置开发文档
├── plugins/          已安装插件，每个插件一个目录
├── LICENSE           MIT 许可证
├── THIRD-PARTY.md    第三方依赖声明
├── data/             运行时生成：config.json / TOKEN.txt / 图片缓存
└── .venv/            运行时生成：Python 虚拟环境

data/ 与 .venv/ 在首次启动时生成，删除后重启会重新创建；注意删除 data/ 会重置配置并换发新令牌。完整版没有额外的兼容层目录，只是多出 OneBot 与微信的接入实现。

接入 QQ 官方机器人

开源版只走 QQ 开放平台：在控制台填 AppID 与 AppSecret，网关地址、访问令牌刷新、心跳与重连全部由程序处理。

三步上线

1 · 创建机器人到 QQ 开放平台（q.qq.com）创建应用，拿到 AppID 与 AppSecret；沙箱环境可先只加自己和测试群。
2 · 加入群或先私聊在开放平台把机器人添加到群，或直接用单聊调试。群聊需要 @ 机器人才会收到事件。
控制台 · 平台连接
新增连接 → 填名称
名称       我的机器人
AppID      102xxxxx
AppSecret  ************************

保存后自动连接 api.sgroup.qq.com 网关
在线状态、重连次数、最近错误都显示在卡片上

默认订阅群 @ 消息、群消息与单聊消息。回复会自动带上原消息 ID，符合开放平台的被动回复要求；主动推送受平台额度限制，插件里不要依赖无上下文的群发。

完整版：OneBot 与微信

完整版在同一页面可新增 OneBot v11、OneBot v12 与 微信官方机器人 三类连接。OneBot 支持两种方向：

server · 平台连入YueWuBot 监听 WebSocket，由 SnowLuma / NapCat 等平台主动连过来，地址 ws://127.0.0.1:6199/ws?conn=名称。
client · 机器人主动连YueWuBot 主动连接平台提供的 WS 地址，适合平台在容器或内网、机器人无法被反向访问的场景。

微信官方机器人使用公众号回调：在公众号后台填写 https://你的域名/wechat/连接ID 与相同 Token，消息经客服接口回复。

容器部署：平台运行在 Docker 中时，地址请指向宿主机网关而非 127.0.0.1，并在容器侧配置 host-gateway。

浏览器打开 http://127.0.0.1:6199，粘贴首次启动生成的 30 位访问令牌登录。控制台包含以下页面：

开发文档内置一份离线文档，部署后无需联网查阅

令牌保存在 data/config.json 与 data/TOKEN.txt，重启服务不会变化；删除 data/ 会换发新令牌，重置令牌后已登录会话立即失效。

模型配置

任何兼容 OpenAI Chat Completions 格式的接口都可以直接接入，只需在控制台填写地址、Key 与模型名。

参数默认值说明
base_urlhttps://api.deepseek.com接口根地址，自动补全 /chat/completions
api_key空服务商密钥，仅保存在本地配置
modeldeepseek-flash模型名称；旧版本名称会自动迁移
temperature0.85采样温度
max_tokens800单次回复最大 token 数
retries3失败重试次数，仅对 5xx 与连接错误重试
timeout8单次请求超时（秒）
system_prompt内置人设系统提示词，可自由替换
visiontrue是否允许处理图片消息

客户端错误（4xx）不会重试，会直接给出明确提示；服务端错误与网络异常按短超时快速重试，避免上游波动时长时间挂起。控制台「测试连接」按钮可用于验证配置是否可用。

消息规则

发送方式行为
普通消息群聊中需要 @ 机器人才会触发对话
/内容以斜杠开头，群聊中无需 @ 直接进入对话
#内容以井号开头，开启快速群对话
#YueWu返回版本、运行时长与运行状态
插件触发词声明了 triggers 的插件可免 @ 全局识别并自动唤醒

插件休眠与唤醒由核心自动管理：只有声明了触发词的插件会被闲置回收，消息到达时按需加载，因此长期运行也不会持续占用内存。

插件开发

插件是一个 zip 包，根目录固定放 main.py 与 m.json，可选 icon.png；其余文件一律放进 assets/。

插件包结构
my-plugin.zip
├── main.py       插件逻辑
├── m.json        元信息
├── icon.png      可选图标
└── assets/       其它资源与数据文件

m.json 字段

字段类型说明
namestring插件显示名称
versionstring版本号
authorstring作者
descriptionstring简介
commandsarray指令名列表，对应 /指令
triggersobject钩子对应触发词数组，用于免 @ 全局识别与按需唤醒
configobject配置表单定义，控制台自动生成输入项
repositorystring源码仓库地址（可选）
m.json 示例
{
  "name": "示例插件",
  "version": "1.0.0",
  "author": "You",
  "description": "一句话说明插件做什么",
  "commands": ["hello"],
  "triggers": { "on_message": ["你好"] },
  "config": {
    "times": { "type": "number", "label": "次数", "default": 1 }
  }
}

main.py 约定

核心会按名称查找钩子函数，支持同步与异步两种写法。常用钩子包括 on_startup、on_filter、on_message、on_group_message、on_private_message、on_notice、on_request、on_config_changed；其中 on_filter 在消息最前置执行，返回 True 可完全拦截该消息；指令函数按 commands 中的名称映射。分发前会注入插件配置，可通过 ctx.cfg 读取，通过 ctx.reply() 回复。开源版没有 OneBot 动作接口，ctx.api() 会直接抛错；完整版在 OneBot 连接下可调用原生接口。

main.py 示例
async def on_message(ctx, event):
    if "你好" in ctx.text:
        await ctx.reply("你好呀～")

async def on_startup(bot):
    pass

def on_config_changed(cfg):
    pass

需要持久化的数据写入插件自己的 assets/ 目录，例如按 QQ 号记录冷却时间；插件目录会随部署一起保留，重启不会丢失。

注意：插件代码以与主进程相同的权限执行，请只安装你信任来源的 zip 包。生产环境建议使用独立低权限账号运行机器人。

排障与维护

控制台打不开确认服务在运行（./start.sh status）、端口未被占用，以及访问的是 127.0.0.1:6199。
机器人一直显示离线核对 AppID 与 AppSecret；查看卡片上的最近错误；确认服务器能访问 api.sgroup.qq.com。
模型回复失败用「测试连接」验证 Key 与模型名，检查 timeout 与 retries；4xx 通常是配置问题。
插件不生效确认 zip 根目录包含 main.py 与 m.json、插件已启用；免 @ 触发需要在 triggers 中声明。

日志可通过 ./start.sh logs 或控制台「日志」页查看。若使用 systemd，也可执行 journalctl -u yuewubot -n 100 --no-pager。
